# 02 后端详解

后端代码位于 `backend/`，是一个 FastAPI 模块化单体应用。

```
backend/
├── app/
│   ├── main.py              # 应用入口： lifespan 建表、路由注册、静态挂载
│   ├── config.py            # pydantic-settings 全局配置
│   ├── database.py          # 异步引擎 / 会话工厂 / get_db 依赖
│   ├── dependencies.py      # 公共依赖：分页、JWT 认证、管理员守卫
│   ├── redis_client.py      # 全局 redis.asyncio 客户端
│   ├── middleware/
│   │   ├── cors.py          # CORS 配置
│   │   └── rate_limit.py    # Redis 固定窗口限流（已挂载到登录/评论/搜索/上传）
│   ├── modules/             # ★ 六大业务模块
│   │   ├── posts/           # 文章/分类/标签/RSS（model/router/schema/service/rss）
│   │   ├── comments/        # 评论
│   │   ├── users/           # 认证/用户/图片上传
│   │   ├── search/          # 全文搜索（无 model，复用 posts）
│   │   ├── stats/           # 访问统计
│   │   └── config/          # 站点配置
│   └── utils/
│       ├── security.py      # bcrypt + JWT
│       ├── markdown.py      # markdown-it 渲染
│       └── slug.py          # 中文标题 → 拼音 slug
├── alembic/                 # 数据库迁移（versions/19c34fbeac15_initial_tables.py）
├── tests/                   # pytest 异步测试（conftest + auth/comments/posts）
├── seed.py                  # 初始数据：admin 用户 + 默认站点配置
├── requirements.txt
├── Dockerfile / entrypoint.sh / alembic.ini / pytest.ini
```

**模块内部统一结构**（posts 为例）：`__init__.py` / `router.py`（路由层）/ `service.py`（业务层）/ `model.py`（SQLAlchemy 模型）/ `schema.py`（Pydantic 请求响应模型）；search 模块无 model（复用 posts），posts 额外有 `rss.py`。

## 1. 应用入口 `app/main.py`

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)   # 启动时兜底建表
    yield
    await engine.dispose()                              # 关闭时释放连接池

app = FastAPI(title=settings.APP_NAME, lifespan=lifespan)
setup_cors(app)
# 7 个 router 统一挂载到 /api/v1
app.include_router(auth_router, prefix="/api/v1")       # users/auth
...
app.mount("/uploads", StaticFiles(directory=settings.UPLOAD_DIR), name="uploads")

@app.get("/health")                                     # 健康检查（无前缀）
```

要点：

- **lifespan**：启动时 `create_all`（幂等，缺表才建）；生产入口 `entrypoint.sh` 会先跑 `alembic upgrade head` 再 `python seed.py` 最后启动 uvicorn。
- **静态文件**：`/uploads/*` 由 FastAPI StaticFiles 直接服务（开发环境）；生产经 Nginx 反代到 backend 容器。

## 3. 数据库层 `app/database.py`

```python
engine = create_async_engine(settings.DATABASE_URL, echo=settings.DEBUG)
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

class Base(DeclarativeBase): ...

async def get_db():
    async with async_session() as session:
        try:
            yield session
            await session.commit()      # 请求成功 → 统一提交
        except Exception:
            await session.rollback()    # 任何异常 → 统一回滚
            raise
```

**核心事务约定**：路由/服务层只调用 `db.flush()`（获取自增 ID / 生效变更），**从不 commit**；事务边界完全由 `get_db` 依赖控制。`expire_on_commit=False` 避免 commit 后访问属性触发额外查询。

## 4. 公共依赖 `app/dependencies.py`

| 成员 | 签名/参数 | 说明 |
|------|-----------|------|
| `Pagination` | `page`(≥1), `page_size`(1~100, 默认10) | 类依赖，计算 `offset = (page-1)*page_size` |
| `get_current_user` | Bearer token → `User` | 解码 JWT → 校验 `type=="access"` → 查库确认用户存在；任何失败返回 401 |
| `require_admin` | `get_current_user` → `User` | 校验 `role == "admin"`，否则 403 |

认证链：`Authorization: Bearer <access_token>` → `decode_token` → `sub`(user_id) + `type: access` 断言 → 数据库实时校验（用户被删则 token 立即失效）。

## 5. Redis 客户端 `app/redis_client.py`

模块级单例 `redis_client = redis.from_url(settings.REDIS_URL, decode_responses=True)`（返回 str 而非 bytes）。Redis 中的键空间：

| 键模式 | 值 | TTL | 用途 |
|--------|----|-----|------|
| `refresh_token:{user_id}` | refresh token 字符串 | 7 天 | refresh token 白名单（登出即删，实现主动失效） |
| `view:{ip}:{slug}` | "1" | 3600s | 文章浏览量防刷（同 IP 同文 1 小时只计 1 次） |
| `rate_limit:{path}:{ip}` | 计数 | window 秒 | 按真实客户端 IP 的固定窗口限流 |

## 6. 中间件 `app/middleware/`

### cors.py — `setup_cors(app)`

包装 FastAPI `CORSMiddleware`：`allow_origins=settings.CORS_ORIGINS`，允许凭证与全部方法/头。生产环境同域反代下基本不触发。

### rate_limit.py — `rate_limit(limit: int, window: int)`

工厂函数返回一个异步 Depends 依赖：

```python
def rate_limit(limit: int, window: int):
    async def dependency(request: Request):
        ip = get_client_ip(request)  # X-Real-IP -> X-Forwarded-For 首个地址 -> client.host
        key = f"rate_limit:{request.url.path}:{ip}"
        current = await redis_client.get(key)
        if current is not None and int(current) >= limit:
            raise HTTPException(429, "Rate limit exceeded")
        pipe = redis_client.pipeline()
        pipe.incr(key); pipe.expire(key, window)
        await pipe.execute()
    return dependency
```

限流已挂载到以下路由：登录 10 次/分、公开评论创建 5 次/分、搜索 30 次/分、管理员上传 50 次/时。refresh 接口不使用该依赖，避免认证失败进入刷新循环。

## 7. 工具 `app/utils/`

### security.py

| 函数 | 说明 |
|------|------|
| `hash_password(password) -> str` | bcrypt 哈希（passlib CryptContext） |
| `verify_password(plain, hashed) -> bool` | 校验 |
| `create_access_token(data: dict) -> str` | 注入 `exp`(120min) + `type: "access"` 后 HS256 签名 |
| `create_refresh_token(data: dict) -> str` | 注入 `exp`(7d) + `type: "refresh"` + 唯一 `jti` |
| `decode_token(token) -> dict` | 解码并验证签名/有效期（失败抛 JWTError） |

token payload：`{"sub": str(user_id), "username", "role", "exp", "type"}`。

### markdown.py

`MarkdownIt("commonmark", {html: True, typographer: True})` + table、strikethrough、front_matter、footnote、dollarmath 插件。`render_markdown(text)` 在文章创建/更新时把 `content_md` 渲染为经过 Bleach 清洗的 `content_html`。
公式使用 `$...$` / `$$...$$`，输出 `data-tex` 与 `data-display` 语义标记，由前台 KaTeX 完成最终显示；fenced code 保留 `language-*` class，由前台 Prism 高亮。清洗会阻断脚本、事件属性和危险 URL。

### slug.py — `generate_slug(text: str) -> str`

中文段（`[一-鿿]`）用 pypinyin 转全拼，英文/数字段直接取词，全部小写以 `-` 连接，清理非法字符与重复横线；空结果返回 `"untitled"`。示例：`"我的第一篇Post"` → `wo-de-di-yi-pian-post`。

## 8. 业务模块详解

### 8.1 users 模块（认证 / 用户 / 上传）

**Model**（`users/model.py`）：`User` — `id, username(unique), password_hash, email?, avatar?, role(admin|editor, 默认 admin), created_at, updated_at`。

**路由**（`users/router.py`，`router` 前缀 `/auth`；`admin_router` 前缀 `/admin`）：

| 方法 | 路径 | 认证 | 处理函数 | 说明 |
|------|------|------|----------|------|
| POST | `/api/v1/auth/login` | 无 | `login` | 校验账密 → 签发双 token → refresh 存 Redis |
| POST | `/api/v1/auth/logout` | Bearer | `logout` | 删除 Redis 中 refresh token |
| POST | `/api/v1/auth/refresh` | 无 | `refresh` | 校验 refresh token 与 Redis 白名单一致 → 签发新双 token |
| GET | `/api/v1/auth/me` | Bearer | `get_me` | 返回当前用户 |
| PUT | `/api/v1/auth/password` | Bearer | `update_password` | 验证旧密码后改新密码 |
| POST | `/api/v1/admin/upload` | admin | `upload` | 图片上传 |

**Service 关键函数**：

- `authenticate_user(db, username, password)` — 查用户 + `verify_password`，失败返回 None（401 由路由抛）。
- `create_tokens(user)` — 组装 payload 生成 access/refresh。
- `store_refresh_token / invalidate_refresh_token / refresh_access_token` — Redis 白名单管理；刷新时旧 token 必须与 Redis 中一致（旋转式刷新，重新签发后旧 refresh 失效）。
- `upload_image(file: UploadFile) -> str` — uuid4 hex + 原扩展名落盘到 `UPLOAD_DIR`；超过 `MAX_UPLOAD_SIZE`(5MB) 抛 `ValueError`（路由转 400）；返回 `/uploads/{filename}`。
- `change_password(db, user, current, new) -> bool` — 旧密码错返回 False（400）。

### 8.2 posts 模块（文章 / 分类 / 标签 / RSS）

**Model**（`posts/model.py`）：

- `Category`：`name, slug(unique), description?, sort_order(默认0), created_at`；`posts` 反向关系。
- `Tag`：`name, slug(unique), created_at`；与 Post 多对多。
- `post_tags`：多对多关联表（复合主键 post_id+tag_id，双向 CASCADE）。
- `Post`：`title, slug(unique), content_md, content_html, excerpt(500), cover_image(500), status(draft|published, 默认 draft), category_id?(FK SET NULL), view_count, is_top, created_at, updated_at, published_at?`；关系 `category` / `tags`。

**路由**（公开 + 管理，tags=["posts"]）：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/posts` | 无 | 已发布列表；参数 `page/page_size/category(slug)/tag(slug)` |
| GET | `/posts/{slug}` | 无 | 详情；非 published 返回 404；Redis 防刷计数 |
| GET | `/categories` · `/tags` | 无 | 列表 |
| GET | `/rss.xml` | 无 | RSS 2.0，最近 20 篇已发布 |
| GET | `/admin/posts` | admin | 管理列表（含草稿），`?status=` 过滤 |
| GET/POST/PUT/DELETE | `/admin/posts[/{id}]` | admin | CRUD；slug 冲突返回 409 |
| POST | `/admin/posts/{id}/publish` · `/{id}/draft` | admin | 发布（写 published_at）/ 下架 |
| POST/PUT/DELETE | `/admin/categories[/{id}]` · `/admin/tags[/{id}]` | admin | 分类/标签 CRUD，slug 冲突 409 |

**Service 关键逻辑**：

- `get_posts(db, offset, limit, category_slug, tag_slug, status)` — `selectinload` 预载 category/tags；排序 `is_top DESC, published_at DESC`；分类/标签过滤用 join；子查询计数返回 `(posts, total)`。
- `create_post` — slug 缺省时 `generate_slug(title)`；`render_markdown` 生成 HTML；excerpt 缺省取正文前 200 字；再绑定 `tag_ids`。
- `update_post` — `model_dump(exclude_unset=True)` 部分更新；content_md 变化时同步重渲染 HTML、未显式给 excerpt 时重新截取；`tag_ids` 提供则整体替换。
- `publish_post / draft_post` — 状态切换；发布时 `published_at = utcnow()`。
- `increment_view_count` — `view_count += 1; flush`（由路由配合 Redis 去重调用）。

**rss.py** — `generate_rss(db)`：feedgen 组装，标题/副标题来自站点配置，链接用 `settings.SITE_URL`，每篇含标题、`{SITE_URL}/posts/{slug}`、excerpt、pubDate；MySQL 返回的无时区 `published_at` 会规范为 UTC，确保 feedgen 可生成有效 RSS。接口目前保留，但前台导航暂不显示入口。

**Schema**（`posts/schema.py`）：`PostCreate/PostUpdate`（更新全字段 Optional）、`TagResponse/CategoryResponse/PostResponse/PostListItem`（`from_attributes=True` ORM 直出；详情含 content_html，列表项不含）、`PostListResponse{items,total,page,page_size}`、`CategoryCreate/TagCreate`。

### 8.3 comments 模块（评论）

**Model**：`Comment` — `post_id(FK CASCADE), parent_id?(自引用 FK CASCADE，支持嵌套回复), nickname, email?, website?, content, status(pending|approved|rejected, 默认 pending), visitor_ip?, created_at`；关系 `post`(backref) / `parent` / `replies`(级联删除)。

**路由**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| POST | `/comments` | 无 | 提交评论；先查 `comment_enabled` 配置，关闭则 403；post_slug 不存在 404；记录 visitor_ip |
| GET | `/posts/{slug}/comments` | 无 | 该文全部**已批准**顶级评论（含 replies 预载） |
| GET | `/admin/comments` | admin | 分页管理列表，`?status=` 过滤 |
| PUT | `/admin/comments/{id}` | admin | 审核（body 传 status） |
| DELETE | `/admin/comments/{id}` | admin | 删除 |

**Service**：`create_comment`（slug → post_id）、`get_approved_comments`（顶级 + selectinload replies，按时间正序）、`get_admin_comments`（倒序分页）、`update_comment_status`、`delete_comment`。

`comment_need_review` 为 `true` 时新评论进入 pending；关闭后新评论直接 approved。管理员可通过 MCP 显式指定评论状态。

### 8.4 config 模块（站点配置）

**Model**：`SiteConfig` — `config_key(unique), config_value?, description?, updated_at`。KV 存储，无固定列。

**路由**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/site/config` | 无 | 全量配置（默认值合并 + 类型转换） |
| GET | `/site/announcement` | 无 | 仅公告内容 |
| PUT | `/admin/site/config` | admin | 部分更新（upsert） |

**Service**：

- `DEFAULT_CONFIG` — 10 个预置键：site_title、site_subtitle、logo_url、favicon_url、announcement、about_content（关于页 Markdown）、footer_text、social_links(JSON 字符串)、comment_enabled、comment_need_review。
- `get_all_config(db)` — 数据库行覆盖默认值；`comment_enabled/comment_need_review` 字符串转 bool；`social_links` JSON 反序列化（失败给 `{}`）。
- `update_config(db, updates)` — 逐键 upsert；dict/list 值 `json.dumps`，bool 转小写字符串，其余 `str()`；`None` 值跳过。

### 8.5 search 模块（全文搜索）

无 model/schema，复用 posts 的模型与响应。单端点：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/search?q=` | q 必填 1~100 字符；`LIKE %q%` 匹配 `title | content_md | excerpt`，仅 published，按发布时间倒序，分页复用 `Pagination`，响应 `PostListResponse` |

### 8.6 stats 模块（访问统计）

**Model**：`VisitLog`（明细：page_path、page_title?、visitor_ip?、user_agent?、referer?、country?、city?、created_at；BIGINT 主键）与 `VisitStats`（按日聚合：stat_date(unique)、page_views、unique_visitors、top_pages JSON——**当前无写入方**）。

**路由**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| POST | `/visit` | 无 | 前端埋点，204；body: page_path/page_title，IP/UA/Referer 从请求头取 |
| GET | `/admin/stats` | admin | 概览：today_pv（visit_logs 当日计数）/ total_posts（已发布）/ total_comments（已批准） |
| GET | `/admin/stats/trend?days=7` | admin | 1~90 天；visit_logs 按日 GROUP BY 输出 page_views 与 distinct ip 的 unique_visitors |

## 12. MCP 管理服务

MCP 入口为 `app.mcp_server:app`，由独立容器以 `uvicorn ... --port 8100` 启动。`app/mcp/server.py` 使用官方 MCP SDK 的 Streamable HTTP transport，工具调用每次创建独立 `AsyncSession`，沿用 backend 的提交/回滚约定。

请求可携带 `?tavilyApiKey=<key>`，也兼容 `X-MCP-API-Key`。API Key 使用常量时间比较，Redis 按密钥指纹和来源 IP 做固定窗口限流；密钥明文不写入数据库或审计日志。工具层只记录工具名、成功状态和耗时，不记录正文、评论内容或密钥。

工具包含文章 CRUD/发布、分类标签 CRUD、评论列表/新增/审核/删除、站点配置读写、统计查询和 Base64 图片上传。破坏性删除必须显式传入 `confirm=true`。认证生命周期（登录、登出、改密码）不作为 MCP 工具暴露。

### 12.1 MCP 管理 API

管理后台使用现有 `require_admin` 访问 `/api/v1/admin/mcp/overview`、`/settings`、`/keys`、`/logs`、`/logs/{id}` 和 `/logs/cleanup`。Key 仅在创建时接收明文，不会再次返回；服务端使用 `MCP_SETTINGS_ENCRYPTION_KEY` 加密并把名称、指纹、末四位、使用次数和最后使用时间返回给后台。请求日志独立事务写入，记录 IP、User-Agent、JSON-RPC 方法、工具、耗时、结果、资源标识及 Key 名称，不记录正文、评论内容、Base64 或密钥。
