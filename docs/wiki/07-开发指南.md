# 07 开发指南

## 1. 前置要求

| 工具 | 版本 | 用途 |
|------|------|------|
| Docker Desktop | 含 compose v2 | 一键启动全套 |
| Node.js | ≥ 20（镜像用 24） | frontend / admin |
| Python | 3.11 | backend |
| MySQL | 8.0 本地实例 | 裸跑后端与跑测试时需要 |
| Redis | 7 本地实例 | 裸跑后端时需要 |

## 2. 启动方式

### 方式一：Docker 一键（推荐，最省事）

```bash
docker compose up -d --build  # 根目录执行；本地直连，不启动 gateway/Nginx
```

启动完成后：

| 入口 | 地址 |
|------|------|
| 博客前台 | http://localhost:3000 |
| 管理后台 | http://localhost:3001 |
| API / Swagger | http://localhost:8000/docs |
| MCP | http://localhost:8100/mcp |
| 默认账号 | admin / admin123（seed.py 创建） |

### 方式二：裸机分别运行（开发热更新）

```bash
# 0) 准备 MySQL(建库 yeyi_blog 与 yeyi_blog_test) 和 Redis

# 1) backend（8000）
cd backend
python -m venv .venv && .venv\Scripts\activate    # Windows
pip install -r requirements.txt
# 可选：backend/.env 写入 DATABASE_URL / REDIS_URL / JWT_SECRET_KEY
python seed.py                                     # 首次：建表+初始数据
uvicorn app.main:app --reload --port 8000

# 2) frontend（3000）
cd frontend
npm install
npm run dev

# 3) admin（3001，已代理 /api 与 /uploads 到 8000）
cd admin
npm install
npm run dev
```

> backend 读取 `.env`（`env_file_encoding: utf-8`）；admin 可用 `.env.example` 中的 `VITE_API_BASE` 指定 API 地址（默认同域）。

## 3. 测试

```bash
cd backend
pytest                # 需要 localhost:3306 存在 MySQL 且账号 root/root
```

- 测试库：`yeyi_blog_test`（每个用例 create_all/drop_all，不影响开发库）
- Redis 全量 mock（conftest `mock_redis`），无需真实 Redis
- 覆盖：`test_auth.py`（登录/token/认证守卫）、`test_posts.py`（文章 CRUD/发布流程）、`test_comments.py`（评论提交与审核）

## 4. 数据库变更流程

1. 修改 `app/modules/<mod>/model.py`
2. 生成迁移：`alembic revision --autogenerate -m "describe change"`
3. 应用：`alembic upgrade head`（全新环境也可依赖启动时 `create_all`）

## 5. 代码约定

### 后端

- **分层**：router（参数解析/HTTP 语义）→ service（业务逻辑）→ model；schema 负责 IO 校验
- **事务**：service 只 `flush()`，不 `commit()`；事务由 `get_db` 依赖统一提交/回滚
- **跨模块**：只 import 其他模块的 `service`，不碰别人的 model 查询
- **新模块**：在 `modules/` 下建同名目录（router/service/model/schema/`__init__.py`），在 `main.py` 注册 router（统一 `/api/v1` 前缀）
- **认证**：管理端点依赖 `Depends(require_admin)`；读取当前用户用 `Depends(get_current_user)`
- **配置**：新增配置项写入 `config.py` 的 `Settings`，环境变量同名覆盖

### 前端（frontend）

- 页面放 `pages/`（文件路由），组件放 `components/`（自动导入，无需 import）
- 数据获取用 `useApi()` + `useAsyncData`（key 唯一；需要总是刷新时传 `getCached: () => undefined`）
- 样式只用 Tailwind + Rocom token class（`rocom-*`），暗色模式由 color-mode `.dark` class 驱动

### 管理后台（admin）

- API 调用统一走 `src/api/*` 模块（axios 实例已带 token 与 401 处理）
- 页面加入 `router/index.ts` 的 AdminLayout 子路由；需要登录的路由继承父级 `meta.requiresAuth`
- UI 组件优先 Element Plus，布局与配色用 Tailwind + rocom token

## 6. 已知限制与待办（代码现状）

以下能力**已有部分基础设施但尚未启用**，开发前请知悉：

1. **限流未挂载**：`app/middleware/rate_limit.py` 可用，但没有任何路由使用它（设计目标：评论 5/分、搜索 30/分、登录 10/分）。
2. **token 静默刷新未实现**：后端 `/auth/refresh` 正常，admin 保存了 refresh_token，但 401 拦截器直接登出。
3. **评论审核状态**：`comment_need_review` 已生效；开启时新评论 pending，关闭时直接 approved。
4. **visit_stats 聚合任务缺失**：趋势数据实时 GROUP BY visit_logs；`visit_stats` 表无写入方。
5. **搜索为 LIKE 模糊匹配**：未建 MySQL FULLTEXT/ngram 索引，数据量大后需优化。
6. **Markdown 服务端插件精简**：仅 commonmark+table+front_matter+footnote；标题锚点（TOC 依赖 h2-h4 带 id）、KaTeX、代码高亮插件未在服务端装配——TOC 正则可能匹配不到无 id 的标题（当前前台 about 页在前端自行渲染）。
7. **CORS 中列出生产域名**：`config.py` 硬编码了 `blog/admin.yeyeyiyi.online`，换域名时需同步修改。

## 8. MCP 本地开发

使用根目录 Compose 本地测试时，MCP 默认 bootstrap Key 由 `MCP_API_KEY` 提供，无需 GitHub Secrets；后台首次登录后在 `/mcp` 的“密钥管理”添加独立 Key。裸跑 backend 时可显式设置 bootstrap API Key：

```bash
cd backend
$env:MCP_API_KEY = "change-me-mcp-key"
$env:MCP_SETTINGS_ENCRYPTION_KEY = "<Fernet.generate_key() 生成的 URL-safe Base64 值>"
uvicorn app.mcp_server:app --reload --port 8100
```

健康检查为 `http://localhost:8100/health`，协议入口可直接使用 `http://localhost:8100/mcp?tavilyApiKey=<key>`；也兼容 `X-MCP-API-Key` 请求头。Key 在 `/mcp` 的“密钥管理”创建，列表只显示名称、指纹、使用次数和末四位。

MCP 工具名统一以 `yeyi_blog_` 开头。列表工具返回 `count/has_more/next_offset`；删除工具必须显式传入 `confirm=true`。开发测试可运行 `pytest tests/test_mcp.py -q`，该测试不依赖 MySQL。

MCP 管理面板开发文件为 `admin/src/api/mcp.ts` 和 `admin/src/views/MCPManagement.vue`，路由为 `/mcp`。后端管理接口位于 `app/modules/mcp/`；新增 migration 后需要执行 `alembic upgrade head`。`MCP_API_KEY` 只用于首次 bootstrap；日常在 `/mcp` 的“密钥管理”添加、启停或删除 Key，Redis 缓存会立即失效。完整 admin 构建需要先在 `admin` 执行 `npm ci`，再执行 `npm run build`。

## 9. UI 视觉调整续作

如果继续颜色与排版任务，先完整读取 `docs/PLAN.md`。前后台当前使用暖纸张主题，用户要求只压深颜色并优化现有 UI/排版，不进行大规模主题重做。修改后运行：

```bash
cd admin; npm run build
cd ../frontend; npm run build
cd ..; docker compose up -d --build
```

本地检查入口为 `http://localhost:3000`、`http://localhost:3001` 与 `http://localhost:3001/mcp`。保留工作区的全部未提交改动，不执行 reset、checkout 或清理操作。
